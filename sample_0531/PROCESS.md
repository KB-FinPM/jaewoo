# PM Agent 프로세스 설명

## 1. 전체 흐름

```text
main.py
 -> pipeline.run_pipeline()
 -> 문서 버전 확인
 -> 기존 분석 여부 확인
 -> DOCX 읽기
 -> Semantic Chunking
 -> Bedrock 요구사항 Atom 추출
 -> Qdrant 저장
 -> RAG 검색 기반 산출물 데이터 생성
    -> 요구사항 Atom
    -> WBS 항목
    -> 화면설계 항목
 -> template 디렉토리의 양식 파일을 읽어 산출물 생성
    -> output/프로젝트명_요구사항명세서_v.0.1.xlsx
    -> output/프로젝트명_WBS_v.0.1.xlsx
    -> output/프로젝트명_화면기획서_v.0.1.pptx
    -> 동일 파일명이 있으면 v.0.2, v.0.3 ... 으로 자동 증가
 -> 토큰 사용량 출력
```

## 2. RAG 적용 방식

1. `input/구축요건정의서.v.X.docx` 파일을 읽습니다.
2. 구축요건정의서 본문을 의미 단위 chunk로 분할합니다.
3. 각 chunk에서 Bedrock을 이용해 요구사항 Atom을 추출합니다.
4. 추출한 Atom을 embedding하여 Qdrant에 저장합니다.
5. WBS와 화면설계서 생성 시 Qdrant에서 관련 요구사항만 검색합니다.
6. 검색된 요구사항을 Bedrock에 전달하여 WBS 항목과 화면설계 항목을 생성합니다.
7. 생성된 데이터를 각 템플릿 파일에 입력해 최종 산출물을 저장합니다.

## 3. 버전 관리 방식

파일명은 다음 형식을 권장합니다.

```text
구축요건정의서.v.1.docx
구축요건정의서.v.2.docx
```

동일 버전이 `output/cache/doc_versions.json`에 존재하면 문서를 다시 분석하지 않고 기존 분석 결과를 사용합니다.

기존 분석 결과가 존재할 경우 다음 메시지를 출력합니다.

```text
기존에 이미 분석한 내용이라 다시 저장하지 않습니다.
```

## 4. 템플릿 기반 산출물 생성 방식

### 4.1 요구사항명세서

사용 템플릿:

```text
template/탬플릿_요구사항명세서.xlsx
```

생성 파일:

```text
output/프로젝트명_요구사항명세서_v.0.1.xlsx
```

프로젝트명에 공백이 있으면 `_`로 치환합니다. 같은 파일명이 이미 있으면 `v.0.2`, `v.0.3` 순서로 자동 증가합니다.

#### 표지 시트

| 템플릿 치환값 | 입력값 |
|---|---|
| `{프로젝트명}` | 프로젝트명 |
| `{작성자명}` | 작성자 |

#### 개정이력 시트

| 템플릿 치환값 | 입력값 |
|---|---|
| `{작성일}` | 오늘 날짜, `YYYY-MM-DD` 형식 |
| `{작성자명}` | 작성자 |

#### 요구사항명세서 시트

템플릿의 `요구사항명세서` 시트에 다음 항목을 컬럼명 기준으로 입력합니다.

| 입력 항목 | 설명 |
|---|---|
| 구분 | 요구사항 구분 |
| 요구사항ID | `REQ-0001` 형식의 요구사항 ID |
| 요구사항명 | 요구사항명 |
| 기능/비기능요구사항 | 기능 또는 비기능 요구사항 내용 |
| 검토의견 | 검토의견. 값이 없으면 요구사항 설명 사용 |

현재 템플릿 기준 주요 입력 열은 다음과 같습니다.

| 항목 | 열 |
|---|---|
| 구분 | B |
| 요구사항ID | I |
| 요구사항명 | J |
| 기능/비기능요구사항 | K |
| 검토의견 | P |

### 4.2 WBS

사용 템플릿:

```text
template/탬플릿_WBS.xlsx
```

생성 파일:

```text
output/프로젝트명_WBS_v.0.1.xlsx
```

프로젝트명에 공백이 있으면 `_`로 치환합니다. 같은 파일명이 이미 있으면 `v.0.2`, `v.0.3` 순서로 자동 증가합니다.

#### WBS 시트

템플릿의 `WBS` 시트에 다음 항목을 컬럼명 기준으로 입력합니다.

| 입력 항목 | 설명 |
|---|---|
| 레벨 | WBS 레벨 |
| WBS명 | WBS 작업명 |
| 산출물 | 해당 작업의 산출물 |

현재 템플릿 기준 주요 입력 열은 다음과 같습니다.

| 항목 | 열 |
|---|---|
| 레벨 | B |
| WBS명 | D |
| 산출물 | H |

### 4.3 화면설계서

사용 템플릿:

```text
template/탬플릿_화면설계서.pptx
```

생성 파일:

```text
output/프로젝트명_화면기획서_v.0.1.pptx
```

프로젝트명에 공백이 있으면 `_`로 치환합니다. 같은 파일명이 이미 있으면 `v.0.2`, `v.0.3` 순서로 자동 증가합니다.

#### 0, 1번 슬라이드

0번, 1번 슬라이드에서 다음 템플릿 치환값을 입력합니다.

| 템플릿 치환값 | 입력값 |
|---|---|
| `{프로젝트명}` | 프로젝트명 |
| `{작성자명}` | 작성자 |
| `{작성자}` | 작성자 |
| `{작성일}` | 오늘 날짜, `YYYY-MM-DD` 형식 |

#### 2번 슬라이드

2번 슬라이드를 기본 모양으로 사용하여 화면설계 항목 수만큼 반복 생성합니다.

| 템플릿 치환값 | 입력값 |
|---|---|
| `{요구사항ID}` | 요구사항 ID |
| `{화면ID}` | 화면 ID |
| `{화면번호}` | 화면번호 |
| `{화면명}` | 화면명 |

#### Description 표

우측 Description 표에는 해당 화면에서 표시해야 할 내용을 입력합니다.

| 제한 조건 | 내용 |
|---|---|
| 최대 입력 건수 | 10건 |
| 10건 초과 시 | 10건까지만 입력하고 이후 항목은 제외 |

## 5. 주요 설정값

`.env` 또는 실행 옵션으로 프로젝트명과 작성자를 지정할 수 있습니다.

```text
PROJECT_NAME=프로젝트명
AUTHOR_NAME=작성자
```

CLI 실행 시에는 다음 옵션을 사용할 수 있습니다.

```bash
python main.py --project-name "프로젝트명" --author "작성자"
```

템플릿 경로는 `.env`에서 변경할 수 있습니다.

```text
REQUIREMENT_TEMPLATE_PATH=template/탬플릿_요구사항명세서.xlsx
WBS_TEMPLATE_PATH=template/탬플릿_WBS.xlsx
SCREEN_TEMPLATE_PATH=template/탬플릿_화면설계서.pptx
```

## 6. 주요 모듈

| 모듈 | 역할 |
|---|---|
| `main.py` | CLI 실행 진입점 |
| `modules/pipeline.py` | 전체 프로세스 오케스트레이션 |
| `modules/version_manager.py` | 문서 버전, 파일 해시, 캐시 관리 |
| `modules/docx_reader.py` | DOCX 문단/표 텍스트 추출 |
| `modules/chunker.py` | heading 및 길이 기준 chunk 분할 |
| `modules/extractor.py` | Bedrock으로 요구사항 Atom 추출 |
| `modules/qdrant_store.py` | Qdrant 저장/검색/스크롤 |
| `modules/rag_service.py` | 도메인별 RAG 검색 로직 |
| `modules/wbs_generator.py` | RAG 기반 WBS 생성 |
| `modules/screen_planner.py` | RAG 기반 화면설계 데이터 생성 |
| `modules/excel_writer.py` | Excel 템플릿 기반 요구사항명세서/WBS 생성 |
| `modules/ppt_writer.py` | PowerPoint 템플릿 기반 화면설계서 생성 |
| `modules/token_tracker.py` | Bedrock token 사용량 집계 |
| `modules/logger_utils.py` | `[HH:MM:SS]` 로그 출력 |

## 7. 생성 산출물

```text
output/
 ├─ 프로젝트명_요구사항명세서_v.0.1.xlsx
 ├─ 프로젝트명_WBS_v.0.1.xlsx
 └─ 프로젝트명_화면기획서_v.0.1.pptx
```

파일 생성 시 프로젝트명의 공백은 `_`로 치환합니다.
동일한 파일이 이미 있으면 기존 파일을 덮어쓰지 않고 minor version을 1 증가시켜 저장합니다.

예시:

```text
테스트_프로젝트_요구사항명세서_v.0.1.xlsx
테스트_프로젝트_요구사항명세서_v.0.2.xlsx
테스트_프로젝트_요구사항명세서_v.0.3.xlsx
```
